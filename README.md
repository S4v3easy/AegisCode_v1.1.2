AegisCode is an AI-powered, multi-language pre-commit guard designed to stop architectural degradation and "AI Slop" before it ever reaches your repository.

---

## 🚨 The Problem: The Rise of "AI Slop"

With the explosion of AI coding assistants (Cursor, GitHub Copilot, ChatGPT), junior developers and fast-moving teams are writing code at unprecedented speeds. This phenomenon, often called **"Vibe Coding"**, produces code that is syntactically correct and passes unit tests, but is a nightmare for Senior Engineers to review.

AI-generated code often:
- Ignores internal company architecture (e.g., querying databases directly from UI components).
- Introduces massive, undocumented rewrites of core logic.
- Hallucinates dependencies or uses deprecated libraries.
- Introduces subtle but catastrophic security vulnerabilities (e.g., swallowed exceptions, raw SQL injection).

## 💡 The Solution: AegisCode

AegisCode sits in your terminal as an uncompromising, automated **Tech Lead**. It intercepts your `git commit`, extracts the diff, and evaluates it using state-of-the-art LLMs (DeepSeek / Qwen) against a set of strict, dynamically generated architectural rules tailored specifically to your project's technology stack.

If your code violates the architecture, AegisCode **blocks the commit** and tells you exactly how to fix it.

---

## 🚀 How It Works (The 3 Pillars)

### 1. Dual-Engine Auto-Discovery
AegisCode mechanically scans your project using a lightweight, infinitely scalable Dual-Engine:
- **Surface Scan:** Detects file extensions to identify languages (e.g., `.rs` for Rust, `.py` for Python).
- **Surgical Extraction:** Parses manifests (`package.json`, `Cargo.toml`, `go.mod`, `composer.json`, `requirements.txt`, `Gemfile`) to identify your exact core frameworks (React, Django, Tokio, Gin, etc.).

### 2. The AI Architect (Qwen)
During initialization (`aegis init`), AegisCode passes your detected stack to the **AI Architect**. The Architect dynamically generates 3 to 5 strict, production-grade architectural rules specific to your stack (e.g., enforcing Boundary Isolation between React and Express).

### 3. The AI Inquisitor (DeepSeek)
When you commit, the **AI Inquisitor** analyzes your Git Diff. It cross-references your code against:
1. **Universal Laws:** Inviolable rules like the *Anti-Slop Doctrine* and *Zero-Trust Security*.
2. **Custom Rules:** The stack-specific rules generated by the Architect.

## ⚙️ Features

- **Severity Profiles:** Choose how strict you want the AI to be.
  - 🟢 **Relaxed:** Sanity checker. Forgives missing tests.
  - 🟡 **Medium:** Standard Mid-Level Engineer Review.
  - 🔴 **Paranoid:** Strict Enterprise Rules. Zero Tolerance for lack of tests or architectural leaks.
- **Stateless Configuration:** Change severity on the fly with `aegis severity` without modifying your rules.
- **Smart Rule Merging:** Run `aegis update` to intelligently merge old rules with new technologies when your stack evolves, featuring a built-in Garbage Collector for obsolete rules.
- **Premium UI:** Beautiful, non-blocking terminal experience using `chalk` and `ora`.

## 💻 Installation & Usage

### 1. Install Globally
```bash
npm install -g aegiscode
```

### 2. Initialize in your Project
Navigate to your repository and run:
```bash
aegis init
```
*This scans your stack, invokes the AI Architect, and generates your `aegis.config.json`.*

### 3. Enable the Git Hook
Turn on the automated guard:
```bash
aegis hook
```
*Select "Enable". AegisCode will now intercept every `git commit`.*

### 4. Code and Commit
Just write your code and commit normally:
```bash
git add .
git commit -m "feat: add user authentication"
```
*Watch AegisCode analyze your changes in real-time. If it's perfect, you'll see a silent `[ ✅ AEGIS VERDICT: APPROVED ]`. If it's garbage, the commit fails and you'll receive actionable feedback.*

### Manage Severity
Too strict? Too lenient? Change the personality of the AI anytime:
```bash
aegis severity
```

## 🏗️ Architecture Note

AegisCode is built with extreme resilience in mind:
- **Registry Pattern:** Scanners and prompts are built using decoupled registries, avoiding `if/else` spaghetti.
- **Prompt Isolation:** LLM Prompts are heavily guarded using XML-like tags (`<IDENTITY>`, `<UNIVERSAL_LAWS>`) to prevent prompt injection from malicious git diffs.
- **JSON Fallback Extraction:** Uses advanced structural anchoring to guarantee valid JSON extraction even when reasoning models (like DeepSeek-R1) hallucinate formatting.
